# unfold english 管理コンソール — Claude Code 実装指示書

> このドキュメントと `miesan-admin-demo.jsx`（UIデモ）をセットで読むこと。
> デモのUI/UX・ブランドトークンを正として実装する。モックデータを実データに差し替えるのが本プロジェクトのゴール。

---

## 0. プロジェクト前提

- クライアント：英語コーチ みえさん（unfold english）。生徒9名→最大20名
- 既存システム：GAS（みえさんGAS.js / v5.x）+ LINE Messaging API + Whisper + GPT-4o-mini/Vision + Google スプレッドシート
- 既存フロー：生徒がLINEで課題提出 → GASがAI分析 → 管理シート「FB候補」タブにFB候補3つを書き込み → みえさんが手動でLINE返信
- 本件のスコープ：**みえさん専用のWeb管理画面（B案）**。生徒側はLINEのまま変更しない
- 非スコープ：生徒向けUI、LINEからの自動FB送信（コピー&ペースト運用を維持）

## 1. アーキテクチャ（最小コスト構成）

```
[各生徒スプシ] ←─ sheetId ─┐
[管理スプシ]                 ├─ 既存GAS（拡張）＝ バックエンドAPI（doGet/doPost, JSON）
  ├ 生徒管理タブ ────────────┘         │
  ├ FB候補タブ                          │ HTTPS + APIキー
  └ 勉強時間ログタブ（新設）            ▼
                              React フロント（Vite）@ Vercel 無料枠
```

- バックエンドは**既存GASプロジェクトに `api.gs` を追加**する形で実装（別プロジェクトにしない。STUDENT_MAP等の既存関数を再利用するため）
- GASを「ウェブアプリとしてデプロイ」（実行ユーザー：自分 / アクセス：全員）し、APIキーで保護
- 月額コスト：0円（Vercel無料枠 + GAS無料）

## 2. スプシ連携の設計（最重要）

### 2.1 原則：生徒管理タブが唯一の接続点

アプリは生徒のスプシURLを一切ハードコードしない。**管理シート「生徒管理」タブを起点に全生徒のシートを動的に解決する。**

生徒管理タブのスキーマ（A〜E列は既存・変更禁止。F列以降を新規拡張）：

| 列 | 項目 | 例 | 備考 |
|---|---|---|---|
| A | user_id (LINE userId) | U5324d... | 既存 |
| B | name | ちあき | 既存 |
| C | sheet_id | 1AbC... | 既存。**これが連携キー** |
| D | status | active / inactive | 既存。inactiveはAPIでも除外 |
| E | segment | A / B | 既存（用途は触らない） |
| F | コース | 英会話力 集中強化 | 新規 |
| G | 開始月 | 2026-04 | 新規 |
| H | 目標WPM | 90 | 新規 |
| I | 月間目標時間(h) | 60 | 新規 |

F〜I列が空欄の生徒はデフォルト値（コース="-", 目標WPM=90, 月間目標時間=60）で返す。

→ **生徒の追加・削除・スプシ差し替えは、この表の編集だけで完結**。デプロイ不要。

### 2.2 生徒スプシ側のタブ規約

各生徒シートは以下のタブ名・列位置を規約とする（既存実装に準拠）：

- `1分スピーチ`：B列=日付, D列=WPM, E列=文字起こし（既存のwriteToStudentSheetと同一）
- `トラッキング`（新設）：A列=教材名, B列=完了範囲数, C列=総範囲数
- タブが存在しない場合はAPIレスポンスで該当セクションを空配列で返す（エラーにしない）

### 2.3 管理シート側の拡張

- `FB候補` タブの実スキーマ（v5.0で実装済み・A〜J列）：
  `A=日時, B=種別, C=生徒名, D=スコア1, E=スコア2, F=文字起こし, G=FB候補①, H=FB候補②, I=FB候補③, J=備考`
- これに**K〜M列を追加**：K=ステータス（`待ち` / `送信済み`）, L=最終FB文面, M=行UUID
  - 既存の `writeFeedbackToAdminSheet` のappendRowを13列に拡張し、K=`待ち`, L=空, M=`Utilities.getUuid()` を付与
  - 既存行（K〜M空欄）は `待ち` 扱いで後方互換。approve時にUUID未付与の行はM列にUUIDを補完してから更新
  - スコア1/スコア2は「`WPM: 88`」「`発音: 7/10`」等の**文字列**。APIではパースせず文字列のまま返し、フロントもそのまま表示する
- `FB候補_v4` タブはv4時代のレガシー。**読み書きしない**（無視）
- `勉強時間ログ` タブ（新設）：A列=日付, B列=生徒名, C列=時間(h)
  - 当面はみえさんが手入力 or 既存トラッキング機能（06）から書き込み

### 2.4 生徒オンボーディングの自動化（B案・メンテ負荷対策）

生徒は自分のスプシを直接閲覧する運用のため、個別シートは維持する。代わりに追加作業を自動化する：

**(1) `createStudentSheet(name, userId)` をGASに新設**
- スクリプトプロパティ `TEMPLATE_SHEET_ID`（生徒用テンプレシートのID）を新規追加
- 処理：テンプレをDriveApp.copyで複製 → 「【生徒】name」にリネーム → sheetId取得 → 生徒管理タブに行追加（A=userId, B=name, C=sheetId, D=active）→ 新シートのURLを返す
- みえさんが使えるように、**管理シートにカスタムメニューを追加**（`onOpen`で「🎓 生徒管理 > 新しい生徒を追加」）。名前とLINE ID（#登録で生徒から届くID）を入力ダイアログで受け取って実行
- これで生徒追加＝「メニューから1回実行」で完結。手動のシート複製・ID転記・規約合わせを撲滅

**(2) `validateStudentSheets()` で規約破壊を自動検知**
- 全active生徒のシートに対し、規約タブ（`1分スピーチ`・`トラッキング`）と列構成の存在をチェック
- 週1の時間主導トリガーで実行し、異常があればLINE通知（notifyMiesan流用）
- 列移動などで連携が静かに壊れる事故を「気づける事故」に変える

## 3. API仕様（GAS doGet / doPost）

すべてのリクエストに `key`（APIキー）必須。スクリプトプロパティ `WEBAPP_API_KEY` と照合し、不一致は `401相当のJSON {error:"unauthorized"}` を返す。

### GET `?action=bootstrap&key=...`
初回ロード用。1リクエストで全画面分を返す（GASは1リクエスト1〜3秒かかるため、画面ごとに分けない）。

```json
{
  "students": [{ "id":"sheetId", "name":"ちあき", "course":"...", "goalWpm":90, "monthlyTargetH":60, "startMonth":"2026-04", "status":"active" }],
  "queue": [{ "uuid":"...", "student":"ちあき", "type":"1分スピーチ", "datetime":"2026/06/12 09:14", "score1":"WPM: 88", "score2":"フィラー: 5 / 流暢さ: 7", "note":"...", "transcript":"...", "fbs":["候補1","候補2","候補3"] }],
  "generatedAt": "ISO8601"
}
```

> 実環境メモ：現在の生徒管理には テスト行2件（Sayaka / Mie）があり、両方とも同じsheet_idを指している。開発中はこの2行で動作確認し、本番移行時にみえさんが実生徒に差し替える。

### GET `?action=student&id=<sheetId>&key=...`
個別生徒の詳細。1分スピーチタブから履歴（月次集計のWPM/件数）、トラッキングタブから教材進捗、勉強時間ログから月次実績を返す。

### POST `action=approve`
Body: `{ "uuid":"...", "finalText":"...", "key":"..." }`
→ FB候補タブの該当行を K=`送信済み`, L=finalText に更新。

### 実装上の注意
- GASのdoPostはCORSプリフライトに対応できないため、**フロントからは `Content-Type: text/plain` でJSON文字列をPOST**する（preflight回避の定石）
- レスポンスは `ContentService.createTextOutput(JSON.stringify(...)).setMimeType(ContentService.MimeType.JSON)`
- 生徒シートの読み取りは bootstrap に含めない（遅いため）。生徒タブを開いた時に `action=student` で遅延取得し、フロント側で5分メモリキャッシュ

## 4. フロントエンド

- ベース：`miesan-admin-demo.jsx` をそのまま Vite + React プロジェクトに移植
- 変更点は最小限：
  1. モックデータ（STUDENTS / PENDING_INIT / STUDY / MATERIALS）を削除し、`useEffect` + `fetch` で bootstrap 取得に置き換え
  2. ローディング状態（クリーム背景にシンプルなスピナー）と空状態を追加
  3. 「送信済みにする」→ `action=approve` をPOST、楽観的UI更新（即座にキューから消す→失敗時に戻す）
  4. 環境変数：`VITE_GAS_URL`, `VITE_API_KEY`（.env.local、リポジトリにコミットしない）
- デザイントークン（色 `C`、フォント `FONT`）・レイアウト・コピーはデモから変更しない

## 5. セキュリティの割り切り（みえさんに説明済みにする項目）

- APIキーはフロントのバンドルに含まれるため、**URLとキーを知っている人はデータを読める**。生徒の個人情報（氏名・学習データ）を扱うため、URLは非公開・みえさんのみに共有
- 将来生徒数が増える/外部公開する場合は、Supabase Auth等を入れるPhase 2として別見積もり
- 書き込み系APIは approve のみ。削除・生徒管理の編集はスプシ直接操作とする（誤操作リスク低減）

## 6. 追加スコープ：03英会話 / 05振り返りシート / 06トラッキング

Webアプリ（Phase 1〜3）と並行して、GASパイプライン側に以下を追加実装する。

### 6.1 〔03〕英会話レビュー

- フロー：`#英会話` でモード設定 → 録音音声をLINE送信 → Whisper文字起こし → GPT分析 → FB候補シートへ（種別=`英会話`）
- 既存v5.0の変更点：`TASK_TYPES.eikaiwa` を `accept: ['audio']` に変更し guide を差し替え、`AUTO_PROCESS_TYPES` に `eikaiwa` を追加。`processEikaiwa` / `analyzeEikaiwa` を新設
- 分析プロンプトの目的（概要mdの03準拠）：会話の中で「言いたそうで言えなかった・言い直した・日本語で逃げた」箇所を検出し、**使いたかったフレーズの自然な英訳**を最大8つ抽出。FB候補3つはみえさんトーンで
- **技術制約（必ず実装に反映）**：
  - Whisperのファイル上限25MB。`fetchLineContent` 後に `blob.getBytes().length > 24MB` なら処理を中断し「録音は10分程度ずつに分けて送ってください」と生徒に案内
  - GAS実行時間上限6分。長尺音声はWhisper往復だけで数分かかるため、**生徒向けガイドで「10分以内のクリップ推奨」と明記**
  - コスト目安：30分録音 ≈ $0.18/回。週1×20名でも月$15程度で許容範囲

### 6.2 〔05〕振り返りシート（月次）

- **スタディプラス連携は見送り**（調査済み：公開APIは教材アプリ→Studyplusへの記録「投稿」専用で読み取り不可。読む手段は塾向け有償SaaS Studyplus for Schoolのみ）。勉強時間はLINE自己申告で代替（6.3と統合）
- フロー：`#振り返り` でモード設定 → 6項目テンプレ（マインド/学習習慣/最大の変化/来月の意識/不安・サポート/英語面の変化）をBotが返信 → 生徒が埋めて1通で送信 → GPTが**項目ごとに**みえさんスタイルのFB候補を生成 → FB候補シートへ（種別=`振り返り`）
- プロンプトには概要mdの項目1〜6の「生徒例→みえさんFB例」をfew-shotとして全文埋め込むこと（引用形式「>」で生徒の言葉を拾って返すスタイルを再現する）
- 月末（25日）にactive生徒へ振り返りリマインドを自動push
- 実装パターンはwriting（テキスト1通で即処理）と同型

### 6.3 〔06〕トラッキング（汎用設計＋毎日ビハインド通知）

**汎用教材設計（教材が生徒ごとに違っても動く）**：
- 管理シートに `教材マスタ` タブを新設：A=教材ID, B=教材名, C=範囲ラベル, D=順序。概要mdの教材リスト（金フレ日英/英日・瞬間英作文青/緑・読解特急2）を初期投入
- 生徒シートの `トラッキング` タブを割当兼進捗表に：A=教材ID, B=範囲ラベル, C=目標日, D=完了日。みえさんが目標日を設定、完了は生徒のLINE報告（`#完了 日英1-50` 形式）でGASがD列に記入
- 教材の追加・変更は教材マスタ＋割当行の編集だけ。**コード変更不要**

**勉強時間の記録**：
- 生徒がLINEで `#時間 1.5` のように報告 → 管理シート `勉強時間ログ` に追記（2.3で定義済みのタブをここで活用）

**毎日のビハインド通知（公式LINE）**：
- 時間主導トリガー（毎日21:00）で全active生徒を判定：①課題=目標日超過の未完了範囲 ②時間=月間目標時間の日割り累積に対する実績
- 達成率は**積み上げ式（累積）を正**とする（プレッシャーとして効かせる方針）。Webアプリ側は累積/月次の両表示を維持
- ビハインド時のメッセージにGPT生成の**補填計画**を含める：不足分を残日数に再配分（例「あと12日で6時間ビハインド → 1日+30分で追いつけます」）+ 未完了範囲の消化順提案
- **トーン・頻度・補填計画の出し方はみえさんと要壁打ち**（励まし:プレッシャーの配合は彼女の指導観に直結するため、文面テンプレはPhase 5着手前にMTGで合意する）。実装はテンプレ差し替え可能な構造にする
- **コスト注意**：毎日push×20名はLINE公式の無料メッセージ枠（月200通）を確実に超える。ビハインド時のみ送信でも超過し得るため、**有料プラン（ライトプラン）前提のコスト試算をみえさん提案に含めること**

## 7. 実装フェーズ（この順で進める）

1. **Phase 1：GAS API**（api.gs追加、FB候補タブの列拡張、checkSetup拡張）— 動作確認はcurlで
2. **Phase 2：フロント接続**（Vite化、fetch差し替え、ローディング/エラー処理）— ローカルで実データ表示確認
3. **Phase 3：デプロイ**（Vercel、環境変数設定、みえさんのスマホ実機で確認）
4. **Phase 4：03英会話＋05振り返り**（processEikaiwa / processReflection、月末リマインド）
5. **Phase 5：06トラッキング**（教材マスタ・#完了・#時間・毎日21:00のビハインド通知＋補填計画）— **着手前にみえさんと通知トーンの合意必須**

### GASデプロイ時の注意（必読）
- 必ず「新バージョン」としてデプロイすること（既存バージョン更新では反映されない）
- スクリプトプロパティは保持される。`WEBAPP_API_KEY` を新規追加
- LINE Webhook URLは変わらない（既存のdoPostと共存させる：`e.parameter.action` の有無でAPI/LINE Webhookを分岐）

- [ ] トラッキングの累積/月次リセット切替が勉強時間ログの実データで正しく計算される
- [ ] 管理シートのメニュー「新しい生徒を追加」だけで、テンプレ複製〜生徒管理への行追加〜アプリ反映まで完結する
